# SeedGlow 홈페이지 콘텐츠 관리

서비스 소개·대표 소개·문의 영역은 기존 내용을 유지합니다. 이력·후기·협력기관은 인증된 Google Sheets 연결 또는 공개 CSV, 아카이브는 네이버 RSS와 기존 홈페이지에 연결돼 있던 블로그 글의 공개 메타데이터에서 서버가 가져옵니다.

이력은 대표 소개 아래 기존 강의·컨설팅·심사별 목록 형태로 표시합니다. 인증된 시트의 `이력_3열보기` 탭 A:C 열을 그대로 읽어 각 열 안의 행 순서와 문구를 유지합니다. 셀 끝의 대괄호 날짜 표기만 제거하며, 교과목명에 포함된 연도는 이름의 일부이므로 유지합니다. 시트의 건수 요약 행은 항목으로 표시하지 않고 실제 항목 셀 수를 코드로 집계합니다. 기존 홈페이지 분류를 추측해 적용하지 않습니다.

컨설팅 후기는 `홈_후기` 탭만을 기준으로 처음 4개를 표시하고 더보기로 나머지를 펼칩니다. 접기로 다시 4개로 줄일 수 있습니다. 시트 후기와 중복되는 별도 고정 인용문은 사용하지 않습니다. 같은 작성자 표기·본문의 반복은 하나만 표시하고, 실제로 동일 후기의 다른 버전임을 확인한 항목은 두 본문이 확인 당시와 일치하고 남길 버전도 게시된 경우에만 중복본을 제외합니다. 단순히 키워드나 업종이 같다는 이유로 합치지 않습니다. 남는 문구와 행 순서는 원본 그대로이며 시트의 행·게시 설정은 수정하지 않습니다. 인터뷰 메뉴에서는 제공된 두 기사의 실제 제목과 대표 사진을 표시하고 원문으로 연결합니다.

아카이브는 처음 6개를 표시하고 더보기로 나머지 최신·기존 기록을 모두 펼칩니다. RSS에서 사라진 기존 글도 누락되지 않도록 이전에 연결된 원문 링크와 마지막 성공 캐시의 기록을 보존하며, 실제 공개 제목·게시일·대표 사진만 가져옵니다. 같은 글의 링크 형식이 달라도 글 번호로 중복 제거합니다. 본문은 저장하지 않으며 스톡 사진을 대신 쓰지 않습니다. 블로그 카테고리 전체 링크도 제공합니다.

## 설정

기본 방식은 **Google Sheets 연결을 승인하고 기존 편집 주소를 사용하는 것**입니다. 시트를 웹에 공개할 필요가 없습니다. 연결한 Google 계정에 시트 읽기 권한이 있어야 합니다. 인증은 Replit 연결이 처리하며 토큰을 코드·로그·캐시에 저장하지 않습니다.

공개 CSV 방식도 선택할 수 있습니다. 이 경우 각 공개용 탭을 **파일 → 공유 → 웹에 게시**에서 CSV 형식으로 게시하고, 자동 재게시 설정을 유지합니다.

기존 환경변수 이름은 호환성을 위해 유지합니다. 아래 값에는 **현재 시트 편집 주소 또는 CSV 게시 주소**를 넣을 수 있습니다. 공유 환경에 설정하면 개발 및 배포 환경에서 사용합니다.

| 환경변수 | 공개용 탭 | 필요한 열 순서 |
| --- | --- | --- |
| `HOME_HISTORY_CSV_URL` | 이력_3열보기 (인증 연결) | 강의, 컨설팅, 심사 (A:C) |
| `HOME_REVIEWS_CSV_URL` | 홈_후기 | 키워드, 후기 본문(게시용), 표기, 게시 |
| `HOME_PARTNERS_CSV_URL` | 홈_협력기관 | 기관명, 게시, 구분, 집계제외, 메모 |

후기·협력기관은 `게시=TRUE`인 행만 시트 순서대로 표시합니다. `FALSE`나 빈칸은 숨깁니다. 인증된 이력은 `이력_3열보기`의 비어 있지 않은 항목 셀을 표시합니다. 기존 이력 CSV 방식은 기간·내용·구분·게시 열과 TRUE 필터를 유지하는 호환 경로입니다. 협력기관 칩은 모두 표시하지만 집계에는 `집계제외=FALSE`인 게시 행만 포함합니다. 집계제외가 빈칸인 경우에도 집계하지 않습니다.

인증된 시트 연결은 후기 **A:D만 요청**합니다. 협력기관은 **A:B와 D열만 요청**하므로 구분·메모 값도 가져오지 않습니다. 먼저 필수 열 이름을 확인하고 나서 메타데이터에 명시된 유한 행 범위만 읽습니다. 공개 CSV는 앞의 허용 열만 파싱합니다. 후기는 게시용 문구를 수정·요약·자르지 않고 모두 표시합니다. 게시용 문구에 연락처가 있으면 새 데이터를 게시하지 않고 오류 상태와 마지막 성공 데이터를 유지합니다. 기업명·개인 이름의 익명화는 게시용 시트 작성자가 확인해야 합니다.

**공개 CSV 주소 자체에 비공개 원문·연락처·메모 열을 게시하면 누구나 주소로 접근할 수 있습니다.** 사이트에서 열을 무시하더라도 원본의 공개를 막아 주지는 않습니다. 별도의 공개용 탭에는 허용된 게시용 열과 익명화된 문구만 두는 것이 안전합니다. 후기 CSV가 4개 열만 있어도 동작합니다.

## 자동 갱신과 집계

- 서버 캐시: 마지막 성공 후 1시간. 동시 요청은 한 번만 가져옵니다.
- 실패 시: 마지막 성공 데이터 유지, 재시도는 1분 간격.
- 브라우저: 같은 사이트의 `/api/home-content`만 1분 간격으로 조회합니다.
- 아카이브 이미지는 `/api/archive-image`로 서버에서 가져오며, 글 본문은 저장하지 않습니다.
- 아카이브는 RSS에 포함된 최근 글 중 `seedglow` 카테고리만 대소문자 무시로 선택합니다. RSS가 전체 블로그의 모든 과거 글을 포함한다는 보장은 없습니다.
- 이력 누적 N건: 3열 이력의 실제 항목 셀 수. 상단 강의/IR 심사: N을 10 단위로 내림해 `N+`.
- 협력기관 제목: 집계 대상 수를 10 단위로 내림해 `N+`.
- 300+, 26팀, 50억+는 기존 고정값 유지.

성공 데이터는 공개 허용 필드만 `.cache/home-content`에 저장합니다. 같은 파일시스템에서 서버가 재시작하면 복원하지만 재배포·새 인스턴스가 이 로컬 캐시를 반드시 이어받는 것은 아닙니다. 새 인스턴스는 출처에서 다시 가져오며, 최초 연결 실패 시 페이지가 깨지는 대신 연결 안내를 표시합니다.

FALSE 확인 방법: 게시 행 하나를 FALSE로 저장하고, 현재 서버 캐시의 1시간 만료 및 다음 1분 자동 조회 후 해당 행과 집계가 함께 사라지는지 확인합니다.


## 홈페이지 사진 최적화

원본 사진은 `attached_assets/`에 그대로 보존합니다. 홈페이지는
`client/src/assets/home/`의 WebP 사본만 사용합니다. 기존 비율·크롭·사진 순서는
유지하며 슬라이더는 300/600/900px, 프로필은 320/640/960px,
첫 화면 사진은 480/768/1024/1299px 중 화면과 픽셀 밀도에 맞게 선택합니다.
첫 화면은 우선 로딩하고, 프로필과 활동 사진은 지연 로딩합니다.

원본 사진을 교체한 경우 아래 명령으로 사본과 이미지 목록을 다시 생성하고
생성된 파일을 함께 커밋합니다. 빌드나 서버 실행 때 원본을 다시 가공하지 않습니다.

```sh
npm run images:optimize
npm run test:home-images
```

`reports/home-image-assets.json`에는 원본 해시·크기와 각 사본의 크기가 기록됩니다.
테스트는 원본 보존, 이미지 디코딩, 비율, 파일 크기와 로딩 설정을 확인합니다.

실행 중인 사이트의 모바일 3x·PC 1x/2x 확인:

```sh
IMAGE_TEST_URL=https://사이트주소 BROWSER_EXECUTABLE=/설치된/chromium npm run verify:home-images:browser
```

Playwright 기본 브라우저가 설치되어 있다면 `BROWSER_EXECUTABLE`은 생략합니다.
결과와 화면 캡처는 `reports/`에 저장합니다. 네트워크 속도 측정이 아니라 실제
이미지 선택·정상 표시·요청 용량·지연 로딩과 슬라이더 동작을 확인하는 검사입니다.

## 콘텐츠 검증

```sh
npm run check
npm run test:home-content
npm run build
npx tsx script/verify-home-content.ts
```

마지막 명령은 실제 연결된 공개 데이터의 행 수·집계·최신 아카이브 제목을 `reports/home-content-verification.json`에 기록합니다. 환경변수 미설정 값은 0이 아닌 확인 대기로 보고합니다.
