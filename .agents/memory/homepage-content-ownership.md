---
name: 홈페이지 콘텐츠 운영 원칙
description: 운영자가 수정하는 구글시트·블로그와 후기 익명화에 대한 사용자 요구
---

이력·후기·협력기관은 운영자가 구글 시트를 수정하면 홈페이지에 자동 반영되는 방식으로 관리한다. 아카이브는 운영자의 네이버 블로그 게시물과 연동한다. 임의의 고정 목록이나 추정 숫자로 되돌리지 않는다.

**Why:** 사용자는 홈페이지 코드를 매번 수정하지 않고 자신의 시트·블로그에서 내용을 관리하기를 요청했다.

**How to apply:** 문구·기간·행 순서는 시트 그대로 유지한다. 강의/IR 심사와 협력기관 집계만 지정한 계산 규칙을 따르고, 다른 기존 수치는 별도 지시 없이 바꾸지 않는다.

사용자는 기존 비공개 시트를 그대로 쓰기 위해 Google Sheets 계정 연결을 승인했다. 운영 시트를 웹에 공개하도록 다시 요구하지 않는다.

**Why:** 편집 주소를 공개 CSV로 바꾸는 대신 현재 구글시트를 쓰기를 요청하고 연결을 완료했다.

**How to apply:** 인증된 서버 연결로 게시용 범위만 조회한다. CSV 게시 방식은 사용자가 선택하는 대안으로만 남긴다.

인증 연결에서 사용하는 시트 편집 주소를 CSV 주소가 아니라는 이유로 잘못된 설정으로 취급하거나 삭제하지 않는다.

**Why:** 다른 작업의 병합이 유효한 편집 주소 설정을 삭제한 적이 있어 다시 복구해야 했다.

**How to apply:** 데이터 연결 방식이 공개 CSV인지 인증된 시트인지 먼저 확인하고 해당 방식의 실제 조회 결과로 설정의 유효성을 판단한다.

후기는 게시용 문구와 익명 표기만 사용하며 요약·절삭하지 않는다. 기업명·이름·연락처를 추가하거나 비공개 원문·메모를 읽고 저장하지 않는다.

**Why:** 사용자가 후기 익명성과 게시용 원문의 보존을 명시적인 원칙으로 정했다.

**How to apply:** 새 후기 기능이나 자동 생성 기능을 추가할 때도 비공개 열을 입력으로 사용하지 않는다. 사이트에서 열을 무시하는 것과 원본 CSV의 공개 범위는 별개의 문제임을 안내한다.

후기는 아카이브처럼 더보기로 나머지를 펼치는 방식으로 보여 준다. 접힌 화면을 짧게 유지하기 위해 후기 본문 자체를 요약하거나 자르는 것은 아니다.

**Why:** 사용자가 “컨설팅후기도 아카이브 처럼 더보기 누르면 더 볼수있게” 요청했다.

**How to apply:** 펼치면 중복을 제외한 게시 후기의 원문을 읽을 수 있게 한다. 더보기는 화면 표시만 바꾸며 시트의 게시 여부를 바꾸지 않는다.

후기의 현재 유일한 기준은 `홈_후기` 탭이며 같은 후기의 발췌본·다른 버전이 카드로 반복되지 않게 한다. 처음에는 4개 정도만 보이고 나머지는 더보기로 펼친다. 시트 후기와 겹치는 별도 고정 인용문을 다시 추가하지 않는다.

**Why:** 사용자가 “지금 시트 홈_후기 탭 기준으로 후기 다시 정리해줘 겹치는 부분 없이 잘 봐주고 4개 정도만 보이게”라고 요청했다. 이전의 별도 파트너십 카드 유지보다 이 최신 기준이 우선한다.

**How to apply:** 시트 원문·남은 항목의 순서·게시 설정은 보존한다. 같은 내용임을 실제 확인한 경우에만 중복본을 화면에서 제외하고, 같은 키워드나 익명 업종 표기만으로 서로 다른 후기를 합치지 않는다. 남길 버전이 삭제·비공개·새 문구로 변경되면 오래된 중복 판정만으로 다른 후기를 숨기지 않는다.

아카이브 더보기에는 최신 RSS뿐 아니라 기존 홈페이지에 있던 과거 글도 포함한다. 사진이 잘리지 않도록 전체가 보이게 표시한다.

**Why:** 사용자가 “나머지 기존 기록들도 다볼수있게” 하고 사진 높이를 높여 잘림을 줄이도록 요청했다. RSS는 최신 일부 글만 제공하므로 RSS만으로는 기존 기록을 보존할 수 없다.

**How to apply:** 확인된 기존 원문 링크를 보존하고 실제 공개 제목·날짜·대표 사진만 조회한다. 동일 글의 다른 링크는 하나로 합치며 본문·대체 스톡 사진을 저장하지 않는다.
